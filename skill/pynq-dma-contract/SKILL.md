# PYNQ DMA 契约

只用于回答“实时帧或显示帧是否安全流动”这一类具体问题。默认离线检查，不导入 PYNQ、不下载 Overlay、不访问寄存器。

最终方案保留 PYNQ 采集与现有 HDMI 链路，电脑虚拟游戏使用已有 Godot；取消的是实体光源及 PYNQ 全虚拟美术交付要求。固定光源、Portal 定位或粒子呈现本身不需要重新设计 DMA。

## 检查顺序

1. 从当前目标源码和已有状态确定一条路径：capture、display 或两者交接。记录实际格式、width/height、有效行字节、stride、span、缓冲数量和帧/代次字段；未知写 UNKNOWN，不猜地址。
2. 只有当前问题涉及制品配对时，核对同次 BIT/HWH/XSA、器件、时钟、地址和版本。文件名、时间戳或单个哈希不能代替配对证据。
3. 沿所有权画出最短顺序：CPU 写 → 同步 → device 读，或 device 写 → 完成 → 同步 → CPU 读。确认 pending/current、帧序号和复用条件，禁止读写仍被另一方占用的槽。
4. 检查异常、超时和退出：相关 DMA 停止并确认 HALTED 后再释放；无法确认时保留缓冲和所有权。不要用 PARK、指针变化或无报错替代完成证据。
5. 先做算术、静态或 host 哨兵检查。只有用户当前任务明确授权时，才做一次已知输入的板端传输/回读；不自动扩展为持续压力测试。

## 对当前游戏的特别要求

- 板端 capture 和 display 共用一个会话所有者，但保留独立角色上下文和非缓存分配；PC 呈现/协议接收不另开板端设备所有者。
- 采集与最终显示目标同为 1280×720；相同分辨率不代表原始格式、BGR 帧、显示像素格式、有效行字节、stride 或 span 相同，仍逐路径核对。
- generation、sequence、captured time 和当前关卡关联必须从采集入口传到检测与游戏提交；PC 接收时间、静止姿态保持或粒子刷新不能替换原始采集标记。
- 素材不是 DMA 缓冲，CPU 不写活动扫描缓冲；stride 不能按有效像素数猜。
- 缓冲、cache 或设备所有权无法证明时，结论只能是 NOT_PROVEN，不能写成通过。

涉及定位或正式游戏接入时按 [最终方案](../../pc_vision/FINAL_PLAN.md) 和 `AGENTS.md` 选择接口；本技能只证明板端帧与缓冲的安全性，不证明多标签姿态、光路或 Godot 游戏正确。

## 输出

最多给出四项：结论、关键数值/证据路径、未覆盖项、最小下一步。没有新发现就引用已有证据，不创建独立契约报告或重复模板。
