# 当前工程适配（按需读取）

本页为工程约束，不是官方对本板的支持声明。以当前仓库文件、用户最新决定及实际目标环境为准；不要复制历史 PASS 或 boot_id。

## 入口与边界

- 状态：`PROJECT_STATE.md` 相关 Current Goal；部署说明：`color_test/software/vision_ps_baremetal/PYNQ_BEAM.md`；教学说明：`pynq_vision/TEACHING_MODE.md`。
- 基线清单：`output/build/game_app/pynq_beam_hardware_5/hardware.json`。候选环境为 ARMv7 hard-float、PYNQ2.6.2、Python3.6；历史镜像 GLIBC2.27 的事实来自本工程文档，真实机器仍须确认。新任务换环境时重新核对，不强行套用旧包。
- 板端继续使用 `beam_launcher.Session` → `beam_runtime.run` → 原硬件 owner。电脑串口后台、Web 与权威 C 游戏会话留在电脑。
- 只接 AI 所需代码/模型；不默认改 PL、BOOT、SD、内核、全局 Python 或启动服务。源码与主机/ARM准备不自动授权设备连接和真实运行。

## 给 AI 一个明确任务

先沿用“确认红色轮廓 → 确认绿色特征 → 黄色光线”。未闭合轮廓不能进入下一阶段，板端只显示当前阶段标记。

AI 可分析绿色特征对应的**未叠加原图 ROI**。先定输出是类别、关键点还是特征向量；类别由模型任务定义，绿色笔划本身不提供类别标签。不要把人工红绿黄线当相机特征训练，或把它们编码成答案泄漏给模型。

需要训练时保存原图/ROI与标签、变换、采集标记；按拍摄批次、视频或物体实例划分训练/验证/测试，避免相邻帧泄漏。未知类和误识别必须进入验证。阈值在验证集确定，测试集不参与调参；未校准分数不称为准确概率（依据 [S5、S7](sources.md)）。

黄色案例目前只用于有限规律拟合；三组方向不同的线不是任意光学规则学习的充分训练集。生成代码仍是上位机可审阅草案，不自动执行、不修改固件或注入正式 C 游戏。

## 运行时兼容门槛

有已验证后端就复用。旧 Python 环境可评估固定版本的 LiteRT/TFLite Interpreter C/C++ 库配 C ABI/ctypes，但不是“官方已支持当前 PYNQ”的结论。先用一个模型和固定 ROI 证明兼容，再接相机。

- 查 ELF 架构、armhf、所需 GLIBC/GLIBCXX 符号和全部依赖；交叉构建使用目标 sysroot，不能靠改版本字符串或覆盖系统 libc 伪装兼容。
- 官方 ARM 示例面向不同设备，可能用 VFPv4/NEON 与较新 GLIBC；不可直接复制其指令集参数或二进制到 Cortex-A9。最新 Python SDK 的要求也不等于 Python3.6 可安装（[S1–S2](sources.md)）。
- 模型格式相同不保证算子/算子版本兼容；默认先验证 CPU 路径。没有已匹配的后端/驱动/硬件证据，不宣称 GPU、NPU 或 FPGA 加速。
- 只在最小浮点链路通过后，按实测评估量化；处理正确的 scale/zero_point、输入范围和输出反量化（[S3](sources.md)）。

## 接入与验收

推理任务只读已安全取得的独立 CPU 副本，不读取设备仍持有的缓冲，不另建 Overlay/MMIO/DMA owner。采集/显示 ticket、整帧提交/退休和确认 HALTED 后释放均沿用原入口。

在 FEATURE 确认等明确事件触发推理。若耗时超出应用预算，使用受限任务队列；模型及解释器并发策略按实际后端确认。结果回原 Session 主线程，以教学会话、模板版本和原帧标记核对；切阶段、重画、NEW 后的旧结果不可提交。

真实运行沿用当前 boot 的受保护准入、实际设备路径和 UART 控制台/占用检查。未获本轮授权时完成离线准备，不生成伪造回执、关闭服务或提供绕过入口。

证明部署至少需要：模型 SHA256/版本、运行时/目标身份、真实原图 ROI 输入、未用于调参的样本结果、板端输出与初始化/预热/稳定推理耗时、峰值内存，以及与原采集显示共同运行的观测。CPU/合成/ARM/实机结果分别记录，未触发项标 NOT_RUN（[S4](sources.md)）。

部署清单最少记录：模型与库路径/哈希、训练/转换版本、目标 ABI/依赖、输入预处理与量化、输出标签/阈值、验证依据及旧版恢复位置。复用现有清单承载，不为每步新增重复报告。
