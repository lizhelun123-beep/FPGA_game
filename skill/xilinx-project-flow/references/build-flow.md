# 阶段与制品身份

| 请求 | 最小输入 | 输出与检查 |
| --- | --- | --- |
| Standalone 应用 | 源码、配置、匹配 BSP/XSA、链接脚本 | ELF/Map；CPU、入口、DDR 范围、栈/堆及依赖 |
| Linux/PYNQ 库 | 源码、目标交叉编译器/sysroot | SO；位数、浮点 ABI、实际动态库版本及导出接口 |
| 启动镜像 | 配对平台的 FSBL/后续引导载荷、BIT、ELF、组合配置 | BOOT 及载荷身份；不能把裸板 BOOT 当 Linux 启动链 |
| PL 改动 | 规范 RTL/BD/IP/XDC、器件、工具版本 | 所需仿真/实现报告、BIT/HWH/XSA 的同次导出 |

每个结果只记录本次有效输入、工具命令、退出码和输出哈希。检查 XSA 内 BIT/HWH 与交付文件一致，地址、时钟、IP 版本与软件一致；SHA256 证明字节身份，不证明电气或运行兼容。

先检查依赖，后启动工具。工具不支持目标环境时定位最小失败，不更改全局安装或为了“有产物”混入旧文件。软件修改复用冻结硬件可减少构建成本；若软硬接口已变，则不能借旧 BIT 跳过所需导出。

反例：UART 编码修改不需要完整 PL 实现；AXI 数据宽度改变却继续使用旧 HWH 则不能按纯 PS 编译交付。复用到新板时替换器件/BSP/时钟/地址及 ABI，不复制原板绝对路径。

启动、下载、复位、写卡是独立动作，按本次授权执行。自定义验收门槛可以接受仿真，但报告中的“执行环境”仍填写 host/RTL/目标设备中的实际一项。
