# 板端 AI 部署

以已训练模型、真实推理调用和目标机结果证明部署。只由主智能体执行，不创建、委派或唤醒子智能体。沿用用户任务与项目授权，不因使用本技能扩大范围。

## 最短入口

- 先读项目当前状态中相关条目、目标入口及已有模型清单；用定向 `rg` 补齐：任务输出、权重来源、目标环境、精度/时延/内存要求。
- 权重缺失时先复用已有数据和训练入口；数据也缺失时，推进可独立的兼容性/接口准备，准确说明缺口。随机权重、硬编码答案和模板代码不能充当识别模型。
- 当前仓库接入必读一次 [PYNQ 适配](references/pynq-linux.md)；仅在版本、算子或构建事实需要核对时，打开 [官方来源索引](references/sources.md) 的对应链接。

## 部署闭环

1. **先排兼容性。** 核对实际 CPU/ABI、Python、GLIBC/GLIBCXX、模型格式、算子版本和后端。复用已验证运行时；没有依据不执行最新版 `pip install`，不升级系统解决兼容问题。
2. **固定输入输出。** 明确原图 ROI、RGB/BGR、尺寸、布局、dtype、归一化、量化参数、类别顺序、坐标映射及未知拒绝条件。主机与板端使用同一契约和固定输入夹具。
3. **验证模型。** 有权重先跑留出样本和导出前后数值对照；仅需训练时才补训练。先获得可复现浮点基线，再按测量决定是否量化；INT8 校准使用代表性数据，校准不替代精度测试。
4. **接入原会话。** 从独立 CPU 副本取输入，结果绑定原会话/帧/阶段/版本；过期结果拒绝。按触发点和实测预算运行推理，保持原采集、显示和串口所有者，不让推理长期阻塞主循环。
5. **逐级验证并打包。** 静态/主机推理 → ARM 编译与依赖 → 获授权的目标机推理 → 原应用闭环。模型、运行时、预处理、标签和版本一同哈希；保存可恢复旧包。只重跑受改动影响或仍有疑点的检查。

## 效率与结论

- 每轮只解决下一项部署门槛；按需读参考，不重载全仓、整本教程或全部日志。版本/输入哈希未变则复用已有证据，联网只核对当前未知项。
- 独立只读检查可批量；构建、修改和依赖步骤顺序执行。相同失败两次无新信息就停该路径，保留原因和最小下一步。
- 最终简述模型/后端标识、改动、已过层级、缺口和下一步。资料齐备、host PASS、ARM 可链接与板端成功分开；没有本次实机结果就写 NOT_RUN。
- 实际安装、连接板卡、改服务/启动链等按本轮授权和项目规则处理；已有授权不重复询问。模型文件落盘不等于推理成功，单模型耗时不等于完整应用帧率。
