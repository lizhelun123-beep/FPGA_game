# Standalone 检查与恢复

启动从匹配的 XSA/BSP、链接脚本和 startup 确认 DDR、保留区、堆栈、异常向量和外设时钟。静态全局工作区与 DMA 分配范围不能覆盖栈、代码或彼此。裸板没有 `/dev`、进程服务或 Linux boot_id；不要执行服务清理指令。

计时换算在平台层完成，避免先乘后溢出；计数回绕按位宽处理。原始采集戳与处理/发送戳分别命名，禁止为通过年龄检查重新盖时间。

MMIO 按芯片文档的访问宽度和屏障接口操作，缓存按 BSP 范围 API 与硬件一致性契约同步。`volatile` 不能排空写缓冲或使 DMA 数据自动可见。定时等待有上限，协议服务不要在高频像素循环里逐字节打印。

| 故障 | 处理边界 |
| --- | --- |
| 检测缺失、歧义或待确认 | 标记当前观测无效，按产品规则保持/清理画面，下一帧继续 |
| 显示栅栏暂未完成 | 保留票据和缓冲，按 IP 状态机等待/恢复，不伪报退休 |
| 相机采集失败 | 保留首错，按已定义的采集通道恢复；不要顺带停止无关显示 |
| 设备所有权未知 | 禁止 CPU 访问/释放活动存储，按文档停机并确认 |

反例：六个候选超出“五种唯一身份”时，应先判定歧义/无效，不能仅因业务数量异常关停健康 HDMI；不能靠截掉第六项假造完整观测。

依据：[AMD AXI DMA Standalone 示例](https://github.com/Xilinx/embeddedsw/blob/master/XilinxProcessorIPLib/drivers/axidma/examples/xaxidma_example_simple_poll.c)。只借鉴匹配版本的驱动/缓存/超时处理，环形显示另按 VDMA 契约。
