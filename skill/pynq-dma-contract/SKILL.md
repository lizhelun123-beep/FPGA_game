# PYNQ Overlay 与缓冲区契约

把“文件可加载”和“数据链正确”拆成可核对的接口契约。适用于帧、音频块、采样块等
PS/PL 共享数据，不依赖本队摄像头、识别类别或固定地址。

## 输入和工作边界

读取目标项目现状及当前限制，再按 [contract-template.md](references/contract-template.md)
填写实际参数。未知项写 UNKNOWN，不猜测 IP 名称、地址、coherent 属性或 I²C 编号。
仅查看已有文件不需要导入 PYNQ。板上环境探测、加载 Overlay、寄存器访问或 DMA 传输
需要当前任务的硬件授权；整理 Skill 和已有上板记录都不代表授权。

## 检查流程

1. **确认产物同源。** 从同一次受控构建记录或 XSA 核对 BIT、HWH、器件、顶层、
   工具版本和哈希。相同文件名、时间戳或单独两个哈希不能证明配对正确。
   不混用另一项目的 BIT、HWH 或裸机 BOOT；不要为解决解析失败先重建全工程。
2. **核对接口。** 对照 HWH、BD/IP 配置和驱动，记录实例、VLNV/版本、基地址/范围、
   DMA 方向、数据/地址位宽、DRE、最大长度、时钟和复位。以目标 IP 的实际配置为准，
   不把 AXI DMA 的 transfer/wait 模式直接套给 AXI VDMA 的二维帧/park 模式。
3. **分开元数据与编程。** 需要试 PYNQ 解析时，先检查安装版本及其 API；确认
   `Overlay(..., download=False)` 的实际语义后才采用。不能因解析异常自动调用
   `Bitstream.download()` 或硬编码 MMIO；只有来源、寄存器映射和驱动兼容性分别
   核实后，才可提出目标板专用兼容方案。
4. **核对内存布局。** 有效行字节=`width × bytes_per_pixel`，缓冲分配至少为
   `stride × height`，且 stride 不小于有效行。多平面、位打包、块格式另列公式。
   CPU 视图必须排除 padding；普通 NumPy 连续数组不自动具备 DMA 可见地址。
   地址位宽、对齐、长度和边界限制来自 IP 配置，不能照搬本队的 32 位/64 字节。
5. **核对所有权与 cache。** CPU 写完成并按实际一致性属性同步到 device 后，才让
   PL 读取；PL 写完成且缓冲不再被写者占用后，按实际属性同步到 CPU，再读取。
   coherent 是经确认的属性。非一致性缓冲缺少 flush/invalidate 或相应同步 API 时
   应报告契约不满足，不能把“没有方法，跳过”当作成功。
6. **核对完成和复用。** 同一个通道只有一个驱动负责。每次提交都对应完成/错误/超时
   和版本或序号；不能读正在采集的槽，也不能覆盖正在显示的槽。环指针复查只能
   降低风险，不能独立证明复制期间无覆盖；保留已验证的 CPU 安全副本，直到所有权
   测试和时序证据允许替换。缓冲在 DMA 停止使用前不得释放。
7. **计算资源与带宽。** 分开列常驻缓冲字节、每帧 capture/display、CPU 读写、cache
   操作和加速器流量。复制 N 字节至少有 N 读+N 写；有效载荷与分配 span 不能混用。
   对 video VDMA 按实际 HSIZE/stride 行为计算 DMA 流量，不默认 padding 也传输。
8. **只选一层验证。** 先做元数据/布局算术和带哨兵 padding 的 host 测试；需要且已
   授权时，才用一个确定输入检查传输、回读、超时和复用，再进入稳态运行。

## 输出

给出已填契约、缺失项、发现与证据、最便宜的下一步。分别标记离线检查、模拟传输、
真实目标板测试；未验证项不提升为通过。跨题目复用时只替换契约和底层驱动适配，
保持黄金算法唯一实现。

## 提炼依据与适用限制

来源工程把 1280×720 BGR888 的有效行 3840 B 存在 stride 5760 B 的缓冲中，
因此单帧分配为 4,147,200 B，有效像素为 2,764,800 B。直接 reshape 或按分配字节
推断有效像素会出错。工程还遇到旧 PYNQ 与新 HWH 的兼容风险和混用构建产物风险。
这些观察支持以上检查顺序；具体数值不是其他项目的默认值。

原适配层做过离线地址/寄存器/stride 测试，但 PYNQ 实板、cache 行为、持续 DMA 和
换板复用尚未验证。本 Skill 是可迁移的审查工作流，不是已经验证的通用 DMA 驱动。
