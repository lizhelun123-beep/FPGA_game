# 按故障选择检查

| 症状 | 最小反例/观测 | 判据 |
| --- | --- | --- |
| 背压丢数据 | 固定序列＋接收端交替 READY | 停顿时 DATA/KEEP/LAST 保持，被接受字节无丢重 |
| 偶发短帧 | 同帧 SOF/EOL、行数、每行被接受字节数 | 行宽/帧高与配置一致，CRC0不能单独替代 |
| 复位后首帧错位 | 在行中/帧间分别复位 | 不提交半帧；首个新完整边界归属明确 |
| Bayer 偏色 | 已知 RAW 色块与奇偶裁剪 | 位打包、BGGR等相位、翻转/裁剪与输出通道一致 |
| RTL 对但目标失败 | 绑定源码/参数到真实 BIT/HWH | 地址/时钟/器件和制品来源配套 |
| 时序/CDC 异常 | 相关时钟域及约束报告 | 解释实际路径，不用无依据 false-path 屏蔽 |

一次只验证一个可证伪假设，先保留失败输入再恢复设备；重复运行应增加信息。被测对象、参数、工具、输入摘要、期望/实际、执行环境构成最小记录，不要求为小改动新建整套报告。

经验：一个“719行且CRC0”的输入足以推翻“CRC0必然代表完整帧”；这是推理反例，不证明硬件一定发生过该序列。测试覆盖必须与结论层次一致。
