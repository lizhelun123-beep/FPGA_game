# 工具链证据门

## 最小证据链

1. 输入身份：器件、工具版本、源码/BD/IP/XDC、配置和脚本哈希或明确路径。
2. 阶段结果：脚本退出状态、日志完成标记、关键报告和输出制品路径。
3. 交接身份：BIT/HWH/XSA/ELF/BOOT 属于同一配置和同一代次，且没有混用旧运行时。
4. 运行边界：离线、host、ARM 交叉编译、真实板端分开记录；能显示、能链接或单次 JTAG 不自动代表实时闭环通过。
5. 清理结果：DMA/VDMA、PS/PL、JTAG 或输入设备的停止/释放状态可证明；无法证明时保留缓冲和所有权，结论为 `NOT_PROVEN`。

## 允许的结论词

- `PASS`：当前任务所声明的范围内，证据链闭合。
- `PARTIAL`：部分阶段通过，至少有明确未覆盖项。
- `NOT_PROVEN`：缺少关键输入、同源绑定、所有权或运行时证据。
- `BLOCKED`：同一原因重复失败且没有更小的可行检查。

## 不应自动做的事情

- 不为补齐外部 skill 的目录结构复制工程或引入第二套 HLS/渲染/检测流程。
- 不因脚本成功、局部 OOC、旧 BIT、固定场景或截图把摄像头实时、HDMI 完整游戏、连续吞吐或板端冷启动写成通过。
- 不为了“修绿”添加没有物理/工具证据的 `false_path`、`multicycle_path`、阈值放宽或地址猜测。
- 不把 skill 调用当作 JTAG、SD、烧录、服务变更或完整 Vivado 构建授权。
