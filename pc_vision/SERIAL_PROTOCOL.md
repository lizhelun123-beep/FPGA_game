# 串口协议 v3

配套固件为 version14，电脑运行层为 `20261030-pc-responsive-7`。v3 不接收 v2 的 ASCII 命令/姿态，也不自动降级。Godot 与网页使用同一个 `BoardInput`。串口仍为115200、8N1、无流控，一个进程独占。

## 包边界

线上完整包：`00 FF | COBS编码内容 | 00`。COBS编码内容内不会出现零字节；接收端按字节推进，不依赖一次读取、换行或字符串结尾。包前后可有启动/诊断文本，文本不会被当作协议消息。接收缓冲有界，截断、超长、校验错误后从下一个边界恢复。

COBS解码后的内容如下，所有整数均为小端：

| 字段 | 字节数 |
|---|---:|
| 固定标识 `52 47`（RG） | 2 |
| 协议版本，固定3 | 1 |
| 消息类型 | 1 |
| 负载长度，不含头部及CRC，最大160 | 2 |
| 负载 | 按长度 |
| CRC32，覆盖前述头部和负载 | 4 |

CRC采用与Python `zlib.crc32`相同的反射CRC32（多项式EDB88320、初值和最终异或FFFFFFFF）。最大原始包170字节，小于254，因此COBS仅增加1字节；完整包最多174字节。CRC、版本、类型、长度以及负载语义全部通过后才提交消息。

## 消息类型与负载

`u8/u32/u64`为无符号整数，`i32`为有符号整数。`level`范围1..15，`generation`是PC会话代次，`nonce`是非零32位PC会话随机数。

| 类型编号 | 名称 | 负载，按顺序 |
|---:|---|---|
| 1 | SYNC3 | nonce:u32 |
| 2 | SYNC3_REPLY | nonce:u32，板端收到完整请求的时间:u64，板端开始发送回复的时间:u64 |
| 3 | LEVEL3 | level:u8，generation:u64，x:i32，y:i32，dx:i32，dy:i32，nonce:u32 |
| 4 | READY3 | LEVEL3全部字段，再附board_ms:u64 |
| 5 | START3 | generation:u64，nonce:u32 |
| 6 | STARTED3 | level:u8，generation:u64，nonce:u32，board_ms:u64 |
| 7 | RESET3 | generation:u64，nonce:u32 |
| 8 | RESET3ACK | generation:u64，nonce:u32，board_ms:u64 |
| 9 | ERROR3 | code:u32，generation:u64，nonce:u32 |
| 10 | POSE3 | 下述完整场景 |

光源x/y使用1/1000相机像素，dx/dy使用1/1000000；与v2的发射条件精度相同。完整LEVEL3为43字节，START3/RESET3为26字节，SYNC3为18字节，均不超过板端64字节RX FIFO。一次只允许一个请求在途；关卡/开始/重置优先于下一次校时。控制超时从完整串口写入完成时刻开始，2秒、最多发送3次，未完整写入不记作发送成功。

只有READY3身份和光源回显一致后才启用开始；新光源画面提交并通过既有显示退休栅栏后，板端才发送READY3。只有匹配的START3才放行POSE3；电脑收到STARTED3才计时。重发幂等、切关与重连的计时/旧帧拒绝契约保持。

## POSE3完整场景

固定负载头为56字节：

| 偏移 | 字段 | 类型 |
|---:|---|---|
| 0 | 关卡 | u8 |
| 1 | PC会话代次 | u64 |
| 9 | PC会话nonce | u32 |
| 13 | 板端发送计数 | u32 |
| 17 | 原始相机generation | u64 |
| 25 | 原始相机sequence | u64 |
| 33 | 原始captured_ms | u64 |
| 41 | 板端打包时published_ms | u64 |
| 49 | valid，0或1 | u8 |
| 50 | 原GameBeam状态码 | u8 |
| 51 | raw_mask | u8 |
| 52 | pending_mask | u8 |
| 53 | missing_mask，仅物理类别 | u8 |
| 54 | 物块数，0..5 | u8 |
| 55 | 几何编码，固定1 | u8 |

每个物块12字节：`类型:u8 | effective:u8(固定1) | x:u16 | y:u16 | 角度:u16 | 长:u16 | 宽:u16`。

- 类型编号和掩码位沿用0=MIRROR、1=PORTAL_A、2=PORTAL_B、3=TARGET、5=WALL；SOURCE不作为摄像头观测发送。
- x/y为1/16相机像素；长宽为1/8相机像素。长宽不丢弃、不从bbox或类别猜测。
- 角度以一整圈65536格编码，解码后生成单位轴。Portal轴仍为solid→ring，旋转与有向语义保持。
- 位置量化误差最多1/32像素，尺寸最多1/16像素，角度最多约0.00275度。这不是毫米精度或实景误差指标。
- 1280×720和restored有效物块语义由协议版本固定，不逐包重复发送。类型重复、越界、非有效标志、非法掩码等整包拒绝。
- 无效/PENDING/STALE输入的物块数必须为0，保留原始帧号、时间、状态和缺失掩码；不发送旧姿态冒充新有效输入。

包括CRC/COBS/包边界，0/3/5物块分别为70/106/130字节；相较v2的124/292/404字节减少约44%/64%/68%。五物块的理论线传输时间由35.1ms降为11.3ms；实际帧率和端到端时延需要上板测量。

## 时钟与显示有效性

电脑记录请求发送前t1、完整回复收到时t4；回复包含板端完整请求被处理时t2、回复发送开始时t3。映射偏移区间为`[t1-t2,t4-t3]`，显式扣除已知板端回复处理时间；剩余区间仍须不超过250ms，并保留原有时钟漂移裕量和5s校时有效期。等待板端轮询之前的时间仍包含在不确定性里，不能声称已消除全部校时延迟。

电脑检查POSE3的关卡、PC代次、nonce，再检查原始帧序和采集时间；完整时钟区间必须满足开始后/本关/600ms准入。显示仍保留上一份完整场景直到新场景就绪，旧画面不刷新采集时间、不回送C计分。2026-10-30用户允许降低电脑准入门槛，350ms放宽至600ms，通关也采用此上限；电脑按选中关卡必需类型适配真实观测，无关额外类别不使整帧失败，必需类型缺失/重复仍由同一C核心拒绝。保留B350及原始时序，当前电脑场景准入由唯一JSON配置为600ms；校时质量上限仍为250ms。

为复用既有Godot/网页控制状态机，Python `ControlFrame.kind`仍使用原内部标签（如READY2）；串口上只有上述v3二进制消息。旧v2编解码器保留用于历史离线回放/测试，正式运行由单一`BinaryParser`解析。

## 验证与部署

C/Python交叉测试覆盖全部控制消息、零字节、所有分片点、CRC/长度/版本破坏、超长、截断恢复、旧协议拒绝、几何误差界和旧关卡拒绝。940份原始实测姿态离线重放的成功/终止/光段数判定一致，光段坐标分量最大变化约0.234像素；这不是新的板端实时通过。

使用新version14 BOOT与新电脑程序成对更新。复制SD/板卡通电由用户执行；关闭旧Python/Godot/网页后台和串口助手后再启动新程序。`--serial-log`保留实际二进制字节的十六进制记录。两个UI入口共用串口运行层，同时只运行一个。
