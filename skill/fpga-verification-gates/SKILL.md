# FPGA 验证与证据审查

围绕一个明确改动建立最小证据链。先读取目标项目现状与已有失败，再填写
[acceptance-template.md](references/acceptance-template.md)。不因竞赛材料整理
自动修改 RTL、替换算法、升级工具或运行全工程构建。

## 黄金参考与分层验证

1. 记录行为黄金实现、输入集、参数/采样相位、整数舍入与输出语义。移植保持一个
   canonical 算法入口，使用 host bridge、适配层或 shadow 比对；不复制检测器或
   物理引擎。不同精度实现先声明逐位相等或数值容差，再测差异。
2. 分开分类正确、中心/方向正确、几何路径正确、时间状态正确和真实显示正确。
   一层通过不代替下一层；保存拒绝样本和反例，不能改测试期望来消除真实回归。
3. 对 AXI4-Stream，数据和元数据只在 `TVALID && TREADY` 时推进。检查停顿时
   输出保持、输入输出像素对应、SOF/EOL、TKEEP、首尾行、复位及连续帧。
   随机背压、边界样本和固定 seed 比单一无停顿彩条更能证明契约。
4. 涉及 ISP 或色彩时，先沿 sensor 原始格式、裁剪/翻转奇偶、有效 Bayer 相位、
   stream 通道和 DDR 字节顺序定位。不要用下游换 R/B 隐藏上游 CFA 错误。
   光学失焦不能由 Gamma、锐化或未经确认的 VCM 软件补偿。

## 来源与构建检查

- 确认被编译的实际源、参数、头文件和版本。打包 IP 的 canonical HDL 改动不代表
  Vivado 已刷新生成的 ipshared；按项目已有脚本核对 checksum、catalog、BD 升级和
  target 刷新，必要时比对实际生成内容，不直接编辑生成副本充当修复。
- BIT/XSA/HWH/BSP/FSBL/ELF/BOOT 只核对当前任务相关组合，建立同次构建清单。
  同名、较新时间戳或编译成功不能替代配置/载荷一致性；沿用已有受控打包器，
  不在 Skill 中复制整套构建/引导工具。
- 初级组同样需要可复现的功能和实现证据。把实际工具版本、依赖、命令、配置、
  输出身份和已知失败写入材料；PYNQ 推荐不构成切换现有运行平台的理由。

## 选择最便宜的有效检查

针对当前假设依次考虑静态/语法、最小 host 比对或单元仿真、OOC、顶层构建。
不是每步必跑；能回答问题就停止升级验证成本。完整构建要有明确必要性并符合用户范围。
保存原失败证据；基础设施失败同一方法最多重试一次，停止无效切换环境或复制工程。
同一技术问题两次失败后汇总证据、尝试和剩余假设，不继续自动扫参。
板上下载、探测、复位及测试须有当前任务授权，已有编译或旧上板记录不代替授权。

## 接受或保留结论

- **功能：** 黄金输出在声明范围内匹配；失败项明确保留。不能把“对象类别全对”
  写成“路径全对”，也不能把模拟截图或固定场景写成真实摄像头链路结果。
- **时序/CDC：** 区分 OOC 和生产顶层，区分 setup/hold 与无约束路径。检查实际
  时钟关系、约束覆盖、WNS/TNS/WHS/THS 和 Critical CDC。负 slack 或未审查 CDC
  不能由局部通过或一张可见画面消除；不为变绿加入无依据 false path/multicycle。
- **性能/资源：** 相同输入、器件、时钟、构建类型和测量边界下对比。production/debug
  分列，报告 post-place 层级 LUT/FF/slice/BRAM/DSP/clock/I/O 以及 DDR 和 CPU。
  资源增加要对应可测收益或必要功能，不以使用率更高作为优化目标。
- **完整性：** 分别给出本次运行、引用历史记录、仍未知的结果。受控 JTAG 启动不
  等同于 SD 冷启动；独立传输测试不等同于持续运行无缓冲争用。

## 失败经验与适用边界

来源工程出现过 canonical Bayer 改动未进入生成 IP 的风险、传感器 BGGR 被按
RGGB 解码导致换色、feature tap OOC 通过但生产 MIPI setup/hold 与 CDC 仍失败。
77 张照片的类别集可全部匹配，而完整光路仅 62 条通过，说明输出必须分层验收。
这些是检查顺序的依据，不是新项目故障的预设答案。

本工作流本次经过静态审查；没有为其运行 Vivado、仿真或硬件测试。新的目标项目
需要提供自己的黄金输入、接口和实现报告，才能得到有效验收结论。
