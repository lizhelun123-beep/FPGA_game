# 实景与虚拟光路游戏集成

先读取仓库 [AGENTS.md](../../AGENTS.md)、[最终方案](../../pc_vision/FINAL_PLAN.md) 的相关段落，以及 `PROJECT_STATE.md` 当前摘要。方案规定目标，状态记录已实现程度；不要把标签已贴好或美术预览通过当成新检测/完整游戏通过。

## 按当前改动定位入口

| 问题 | 复用入口 | 必须核对的边界 |
| --- | --- | --- |
| 固定逻辑光源 | `pc_vision/game_config.json`、既有生成器、C `game_session.*` / `ray_game.*` | 实体必检清单与关卡发射器分离，开始/缺失/重置不再依赖实体 SOURCE |
| Portal 定位 | `vision_ps.*`、`game_scene_adapter.*` | 同一检测入口集成 AprilTag，联合已知局部角点，保留观测质量 |
| 有效边界 | `ray_game.*`、实测模板与原有模型几何 | 有限反射面/入口与画出的有效边界一致，外观不替代碰撞 |
| 姿态稳定/丢失 | `vision_stabilizer.*`、`pc_vision/game_scene.py` | 一处权威稳定输出，角度微调/原地旋转、受限观测和超时均正确 |
| 正式界面 | `pc_vision/native.py` 的 NativeGame、`scene_protocol.py`、`godot/` | 同一快照、原始标记、720p 坐标、输入请求与权威计时结算 |

这些入口均相对仓库根目录；C 源位于 `color_test/software/vision_ps_baremetal/src/`。按当前问题选择工作包，无需按整份方案顺序重做。

## 固定发射条件

- 每关在唯一游戏配置定义发射点、单位方向与坐标空间。每关固定首段发射条件，后续光路继续根据实物求最近交点。
- 同步修改关卡实体数、身份验证、SOURCE 缺失分支、开始/切关/重置与生成配置。求解器内部保留 SOURCE 对象是可行实现，但不得把配置光源放进摄像头观测或伪造采集标记。
- 其他必需实物仍来自可靠的新鲜观测；不以固定光源或 START 补齐缺失物体、制造命中。

## 标签与真实几何

- 2026-10-27 用户最新实测覆盖此前尺寸记录。Portal A 的 ID 为 10/11/12，B 为 20/21/22；字典为 `tag36h11 / DICT_APRILTAG_36h11`。标签黑白主体为 12×12 mm，`tagsize=12 mm`（以米传入时为 `0.012 m`）；白边与裁切外框不计入该值，不推断未测的整贴纸尺寸。
- 两个 Portal 外形均为 80×25 mm；标签中心相对 Portal 几何中心为 `(-30,0)`、`(+30,0)`、`(0,+6)` mm，+x 从左标签到右标签，+y 定义为偏置标签所在侧。标签实际朝向仍与实贴照片核对，运行配置使用这组实测布局。Portal 没有中心线、圆或圆环识别标记，不再用旧圆环规则恢复朝向。
- Mirror 外形 80×25 mm；两个黑点直径 8 mm，中心位于长轴 `±27 mm`，中心间距 54 mm；中间白线长 46 mm，用作有限反射段。
- Wall 外形 80×25 mm；两端白标记沿长轴宽 9 mm，外缘各离对应短边 5 mm；中心为长轴 `±30.5 mm`，中心间距 61 mm。Target 为直径 30 mm 的圆。
- 用户已否定所给 CAD/模型 ZIP 的尺寸；曾从中测得的 80×20 mm 等数值不得进入运行配置或继续用于模板推导。参考照片/mm 模板正在接入，全局相机/棋盘平面标定尚未完成，不宣称毫米精度或实时实景闭环通过。
- 联合可见标签角点恢复整体姿态，并检查拟合残差、标签间距与可见分布。初版三标签正常更新，两标签按质量判断，一个标签只作受限恢复线索；不能只平均中心/角度。
- 先去畸变并建立平面映射。标签面高度与棋盘不同则补偿高度或使用同高度标定，抬起/倾斜超出平面模型时降级；不要声称未实测的毫米精度。
- Mirror 使用明确的有限反射面；Portal 保留长侧入口与配对传送，端面不传送；Target 保留已有圆形命中语义。入口有效长度和偏移单独实测，类椭圆外形或 Tag 外框不直接作为碰撞几何。
- 同时检查相机像素、棋盘毫米和显示像素；从模型/光路使用的同一模板画有效边界、交点和法向。历史虚拟尺寸不能直接改名为毫米。

## 防抖比较与场景有效性

- A 为连续自适应滤波，B 为死区、迟滞与短时可靠观测确认；初版建议 B，保留 A 比较。同一原始录像比较静止交点抖动、移动响应、微调和遮挡恢复，再选择默认实现。
- 修正旧 Portal“位移/尺寸变化才能更新方向”的限制，位置或角度均可触发。Mirror 的轴按 180° 等价处理，Portal 用标签身份定义有向角度，绕 ±180° 时正确解环。
- 阈值由静止噪声、角度误差对光路的放大和边界裕量决定，不能照搬旧像素/角度常量。确认时长结合实际有效输入频率，不机械等待固定帧数。
- 稳定器未得到新鲜可靠支持时，保持姿态属于 HELD/STALE；旧 confirmed 数组不能无期限作为有效观测提交。显示保留与游戏有效期分开，6 s 显示上限不改变 C 的 250 ms 新鲜度契约。
- 单个场景原子提交模型与全部光段。保留 generation、sequence、captured time、level、坐标空间及质量语义；跨设备明确时钟转换。`scene-v1.capture_ms` 是处理开始时间，不假定为曝光时间。

## 一份游戏状态与两种呈现

- 按部署选择板端或 PC NativeGame 作为本局唯一权威 C 会话。两屏显示同一局时消费该会话的有效场景、完整光段、计时和结算，不各自判定通关。
- 统一 1280×720、16:9；旧 NativeGame 1280×800 BGR、菜单和鼠标布局须随同一配置迁移。1280×800 屏幕保持比例，不能变更相机格式或拉伸画面消除留边。
- 实景光段映回相机像素，虚拟模型映到游戏区；中心、方向参考点、边界和粒子共用对应变换。Godot 复用现有美术，只呈现权威结果，普通 GameView 和 art_preview 均非正式游戏验收。
- 沿段粒子、交点火花及 Portal 进出效果仅装饰；事件需匹配当前关卡和帧。终止点后不续画、Portal 两端之间不连实线，STALE 不产生成功效果。
- 计时/星级继续由 C 会话决定：明确开始后 180 s，命中且 `<60/<120/<180 s` 为 3/2/1 星，超时 0 星；不因界面动画或保留的旧画面通关。
